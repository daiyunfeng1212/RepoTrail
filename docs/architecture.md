# 当前结构与学习边界

## 当前只有启动链路

```text
源码运行：run.py ───────────────┐
安装后运行：repotrail 命令 ─────┼→ cli.main() → argparse → 帮助 / 版本
模块运行：repotrail.__main__ ──┘
```

源码运行由 `run.py` 加入 `src/` 搜索路径。安装后，构建工具根据 `pyproject.toml` 注册命令入口。模块运行需要先安装项目或设置 `PYTHONPATH=src`。三种方式复用同一个 `main()`，不复制业务逻辑。

`__init__.py` 目前只保存版本信息。当前不预先定义图节点、解析器基类、数据库或插件注册器，实际需求出现后再设计。

## 后续职责边界

下列都是规划，目前没有对应实现：

- 文件扫描：决定读取哪些文件。
- 语法解析：使用 Tree-sitter 和对应语言语法包获得语法树。
- 信息提取：按语言提取函数、类等信息，转换为项目自己的数据结构。
- 关系分析：根据作用域、导入等信息判断符号关系，与语法解析分开。
- 存储与导出：保存已提取的数据，不承担分析逻辑。
- 展示：消费图数据，不直接依赖语法树内部结构。
- 运行追踪：将来独立设计；静态调用关系不代表实际执行顺序或数据流。

多语言是项目目标，Python 是第一种验证语言。不会把“安装了多个语言解析器”描述成“完成了多语言仓库理解”。

下一轮只实现目录扫描，不同时接入解析器或绘图功能。
