# RepoTrail 首版需求分析

状态：需求已于 2026-11-15 经开发者确认；本文描述待实现和待验收的目标，不代表当前能力。

## 1. 背景与定位

开发者接触陌生仓库时，需要先认识主要模块，再找到与某个业务问题或修改需求相关的代码。目录结构不能完整表达功能职责，一次展示大量符号也会增加阅读负担。

RepoTrail 是面向开发者的本地代码库导读工具：理解用户的问题或修改目标，结合源码结构、图谱和文档定位相关代码，提供可核对的解释与阅读、修改入口建议。

简历展示和 Agent 开发学习是项目建设目标；产品验收以实际代码定位和导读效果为依据。

## 2. 用户与使用边界

- 面向加入陌生项目、学习开源仓库或定位修改位置的开发者。
- 首版为本地单用户应用，通过浏览器查看图谱、源码和问答。
- 每次分析一个本地仓库，先用中小型真实仓库验证，记录其文件数、代码量和语言组成。
- 只读取和分析目标仓库，给出建议；不自动修改源码或执行目标仓库中的程序。
- 仓库与分析结果保存在本机；允许使用用户配置的外部模型 API，仅发送完成任务所需的片段。

## 3. 核心使用流程

1. 用户选择本地仓库和分析模式。
2. 系统建立轻量结构索引，生成有依据的模块概览。
3. 用户逐层浏览，或用自然语言提出问题、描述修改目标。
4. Agent 根据意图调用检索、关系查询和源码读取工具；必要时触发局部深入分析。
5. 系统返回定位结果及依据，同步高亮相关图节点；用户点击引用查看源码。
6. 意图不明确时澄清，证据不足时说明限制，源码变更后标记相关结果待更新。

## 4. 首版功能需求

### FR-01：仓库接入与资料读取

- 收集目标仓库中的源码、README、Markdown 文档和基础项目配置。
- 提供过滤规则，排除版本控制数据、依赖产物及密钥文件等不应参与分析的内容。
- 明确报告被过滤、无法读取或暂不支持的文件，避免将读取失败当作没有内容。
- 工具读取范围限制在用户选择的目标仓库内。

### FR-02：分级语言支持与结构提取

| 支持级别 | 首版行为 |
| --- | --- |
| 已验证的结构分析 | 先覆盖 Python，提取文件、类、函数、源码位置、导入及明确支持的关系 |
| 文本检索与 AI 解释 | 其他可读取源码仍可参与定位，明确标记其结构和关系未经过解析器验证 |
| 尚不可读取或分析 | 显示原因与能力限制，不伪装成分析成功 |

- 结构分析统一为节点和关系数据，至少逐步验证包含、导入及能够确定的调用关系。
- 使用 Tree-sitter 与相应语言规则逐种扩大结构支持范围，参考 Understand-Anything 的语言配置、专用提取器、提示片段和测试样例。
- 区分语法包可用、语法解析成功、结构提取完成和关系已确认；配置数量不能当作已验证语言数量。
- 解析失败、能力未支持和确实不存在符号，应有不同的结果说明。
- 静态调用、依赖关系不等同于真实运行轨迹或完整数据流。

### FR-03：功能模块概览与人工修正

- 以功能职责组织概览模块，例如用户认证、订单处理，不要求模块与目录一一对应。
- 结合目录、文档和源码证据，展示模块名称、职责、文件范围和已识别的模块关系。
- 证据不足的职责说明标为“初步判断”，允许继续细化。
- 用户可以修正模块名称和文件归属，系统保存这些修正。

### FR-04：生成模式与按需分析

- 默认采用“概览优先”：先建立轻量全仓结构索引和模块概览，进入模块或问答需要时再生成详细解释。
- 提供“预先完整分析”：提前生成当前支持范围内的详细结果，后续读取已有结果。
- 两种模式使用一致的数据含义和浏览层级；“完整”仅指当前支持范围，不承诺生成所有知识。
- 按需分析时保留跨模块引用，不因当前只分析一个模块而丢失已知外部关联。

### FR-05：分层浏览与源码导航

- 支持从模块逐层进入子模块或文件，再到类与函数；层数根据实际结构调整。
- 显示当前浏览位置并提供返回上层的入口。
- 区分“尚未分析”与“没有内部内容”。
- 点击源码引用可查看相应文件与位置，问答定位结果同步高亮图节点。

### FR-06：意图驱动的代码定位

- 接收功能问题或修改目标，将意图转为检索步骤，结合节点内容和关联关系查找候选代码。
- 由 Agent 选择节点搜索、关系查询、源码读取等工具，程序负责校验参数和执行。
- 一次检索不足时允许继续查询，保留本次任务中必要的上下文与澄清结果。
- 意图不明确时展示候选差异或提出澄清问题；没有依据时明确说明，不强行给出唯一答案。
- 首版先实现单 Agent 的定位闭环。

### FR-07：回答与证据

每次定位回答应按实际可获得的信息提供：

- 相关文件或符号及源码位置。
- 定位理由和支持结论的源码、文档依据。
- 已确认的上下游关系，以及尚无法确定的部分。
- 建议优先阅读或修改的入口及理由。

源码事实、文档描述和 AI 判断应有明确区分。引用需要对应实际读取的源码版本；行号存在不等于该位置支持结论。

### FR-08：缓存、源码变化与手动刷新

- 已完成且仍有效的分析结果可以复用，重复请求不应重复创建相同任务。
- 首版由用户手动触发刷新；系统识别源码变化，将相关结果标为“待更新”。
- 刷新时复用仍有效的结果，更新已变化文件及受影响的分析内容。
- 过期结果和引用不能继续作为当前事实展示。
- 保留用户修正；源码变化使修正失效时提示用户处理，避免直接覆盖。

### FR-09：任务进度、取消与失败处理

- 区分未分析、排队中、分析中、已完成、失败、待更新和已取消等状态。
- 根据实际工作量报告进度，允许用户取消任务，保留已完成结果；取消后停止派发后续工作，并尝试中止进行中的请求。
- 明确报告失败原因和重试入口，保留已有可用结果，不将部分失败包装为全部成功。
- 对适合重试的临时错误进行有界重试。

### FR-10：模型调用与运行约束

- 用户自行配置模型接口和凭据，首版先接通一种接口；具体供应商和模型在接入前确定。
- 凭据不写入源码、分析报告或普通调用日志。
- 仅发送必要资料片段，不默认一次上传整个仓库。
- 为模型调用设置轮数、并发、超时和预算限制，达到限制后显示原因及已有结果。
- 记录必要的工具调用、任务状态、耗时和 Token 用量，便于调试及评测。
- 具体默认参数依据模型限额和首次实验确定，不提前承诺固定成本与时延。

## 5. 验收方式

首批准备约 20 个问题，为每题记录人工确认的参考位置、可接受答案或应澄清／无答案的原因，覆盖明确符号、业务描述、含糊需求和仓库不存在的功能。

| 验收项 | 通过依据 |
| --- | --- |
| 代码定位 | 命中的文件和符号与人工确认的位置相符，解释有证据 |
| 源码引用 | 引用真实存在、对应当前版本，并支持关联结论 |
| 歧义与无答案 | 能澄清或展示候选；找不到依据时明确说明 |
| 分层导航 | 可从模块进入相关细节并返回，点击引用能定位源码 |
| 生成模式 | 概览优先不提前完成全部细粒度语义分析；按需深入可产生相应结果 |
| 缓存与任务 | 有效结果能够复用，重复请求不会重复分析，任务状态可核对 |
| 更新与人工修正 | 源码变化后标记待更新；刷新保留有效结果与用户修正 |
| 支持级别 | 未支持语言、解析失败和真实空结果能够区分 |
| 取消与异常 | 取消、失败或达到限制后有明确反馈，已有结果可用 |
| 操作边界 | 只读目标仓库，不越界读取、修改或执行源码 |

记录验收仓库的版本、文件数、代码量、语言组成、模型及调用参数，并统计定位正确性、引用准确性、耗时和 Token 消耗。性能目标和后续对比基线在初次测量后制定，不编造提升比例。

具体验收仓库、问题清单、模型及调用默认值尚待准备或实验；本文不宣称已通过以上验收。

## 6. 后续规划

以下能力不作为首版验收要求：

- 自动修改源码、自动运行目标仓库或验证修改。
- 真实运行追踪与输入场景的实际执行路径。
- 多 Agent 协作。
- 跨仓库关系与大型 monorepo 的专项支持。
- PDF、图片和视频资料分析。
- 云端仓库托管、账号系统、团队权限与多人协作。
- 文件监听或 Git Hook 自动触发分析。
